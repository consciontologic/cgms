# Held-out evaluation v2 — defect-repair amendment

Written before the revised-engine campaign begins. The original
[preregistration](gameplay-heldout-v1.md) still defines estimands, 1,000 blocks per
population, rotations, lineups, practical effects, confidence procedure and target
completed-game replay counts. No economic/pressure policy parameter or held-out
score-based decision changed.

The engine-v2 campaign was interrupted after independent privacy review found
unfinalized private financial totals/scores in public report projections. A
separate **development** random-opponent run found a missing deterministic
continuation when an accepted response window had no eligible responders.
Engine `cgms-engine-v2.1` adds authenticated `resolve-ready` and public schema v2
redaction. Exact financial trajectories now live in explicitly restricted
omniscient artifacts. Public metrics now count real gameplay policy decisions
instead of incorrectly reporting zero. Standalone runs receive the same 100,000
policy-operation default already frozen for the tournament; tournament budgets
are unchanged.

The retired campaign is immutable at
`sims/artifacts/gameplay-heldout-v1-20260930/`: six three-player games financially
finalized, zero four-player games started. The 108.83-second campaign was stopped
during replay; a separate replay using its original saved binary verified all six.
Keep its 14,000 planned-game denominator and interruption visible. Do not pool
these six with the revised campaign or count reruns as independent seed blocks.
Earlier reports remain restricted; do not publish their financial aggregates.

The revised campaign repeats the **same private roots, block identities, paired
chance derivation and frozen heuristic lineups** under a new engine/binary hash.
No held-out effect estimate or policy selection informed these repairs. This is
an engineering replacement, not a favorable-seed selection. Old outputs are not
overwritten. New public templates are `gameplay-heldout-{3,4}p-v2.json`; actual
private copies and all hashes are frozen in the new campaign plan.

Allocate **1,600 seconds** and **1.75 GiB** to the revised campaign, preserving the
original total initial allocation of 1,800 seconds/2 GiB with room for the retired
run and replay. The same fixed population-interleaved one-block shards, first-shard
one/four-worker comparisons, replay requirements and no-result-based-stopping rule
apply. If limits prevent completion, report exact missing targets and immutable
resumable state. Do not infer adequate precision from the small initial allocation.

Separately, `gameplay-random@v2` changes only financial sampling to uniform action
class then uniform entry, addressing a **development** proposal-history loop.
It is absent from the held-out candidate/baseline lineups, and its diagnostics are
not evidence of pressure-versus-economic strength. Its v1 predecessor and failed
artifacts remain retained. No accepted game rule changes in this amendment.
