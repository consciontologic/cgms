# P01 native engine comparison probe

Experimental local tooling for [P01](../../docs/planning/ROADMAP.md), not a
Flutter app or production offline engine. The cgmsart presentation host/package stays in
`client/`. No UI, online authority, entitlements or game rules change.

## Reproduce

From the repository root, with existing Go, Dart and C compiler installations:

```bash
xops/agent/safe-run.sh offline-probe -- python3 xops/offline_probe.py my-fresh-run
```

An optional existing Linux x86_64 NDK directory enables compilation for Android
ARM64/API 23:

```bash
xops/agent/safe-run.sh offline-probe -- python3 xops/offline_probe.py my-android-run --android-ndk /path/to/existing/ndk
```

Use a fresh run ID each time. Outputs are private, ignored files under
`sims/artifacts/offline-probe/<run-id>/`: synthetic request/expected fixtures,
shared libraries/generated C headers and `report.json`. The report records
artifact/source SHA-256 values, toolchain versions, two fresh-process runs,
RSS samples and latency percentiles. Go dependencies must already be cached;
the runner disables Go proxy/checksum network access. Dart uses only its SDK.
No system dependencies are installed and no device configuration is changed.

The runner executes Go race tests and vet, builds the C library, analyzes Dart,
and runs the Dart verification script in two fresh processes. Assertions throw
without requiring Dart's optional `--enable-asserts`. Each population receives
five warmups, thirty timed calls, a Dart JSON roundtrip and two concurrent
isolate calls. Timings include allocation/copy, Go decoding, all trace steps,
observations, a narrow heuristic decision where available, encoding and copying
back to Dart. They are neither isolated bot-decision timings nor mobile budgets.

## Contract and scope

`cgms-offline-probe-v1` accepts `schema`, a synthetic Go board `state` and at
most sixteen `commands`. It validates the physical partition and initial
position (at most sixteen exposed series cards), then records initial and
successor states, events, all seat-limited observations and a deterministic
`heuristic@v1` decision using the existing narrow combat menu. The bot receives
only its own authorized observation. The probe response as a whole is
**omniscient research data**, never a presentation or online response.

The fixtures exercise three/four-player physical Club expenditure, ordered
response passes, hidden hand/Ace counts and faces, restored pending actions,
wrong-game rejection and hidden restriction noninterference. Go tests assert
card outcomes independently; Dart compares every returned byte against the
current Go oracle. This checks the ABI/serialization adapter, **not independent
Dart board adjudication**. The separate financial candidate below supplies
independent Dart ledger transitions. Complete gameplay menus, random decisions,
save-file storage, beginner tutorials and difficulty evaluation remain open.

The C header is generated by Go's `-buildmode=c-shared`. Three functions are
exported:

| Function | Contract |
|---|---|
| `CGMSProbeAlloc(int32_t)` | Allocate 1..4 MiB through the library's allocator. Invalid sizes return null. |
| `CGMSProbeFree(void*)` | Free each allocated buffer exactly once; null is allowed. |
| `CGMSProbe(input, length, output, capacity)` | Positive output byte count; -1 invalid sizes/null buffers, -2 insufficient capacity, -3 recovered internal panic. |

Callers supply valid, non-overlapping buffers for their declared lengths. A C
ABI cannot establish that an arbitrary non-null address is safe. The Dart
adapter owns and frees both buffers in `finally` blocks and copies returned
bytes before freeing. No Go pointers or persistent game handles cross the ABI.
Calls are synchronous, non-leaf FFI calls; a future app must use a worker isolate.
The Go shared runtime stays loaded for process lifetime; this probe does not
claim safe dynamic unloading, mobile suspend/resume or memory-pressure recovery.
Strict canonical JSON rejects unknown/duplicate keys, floats, incompatible
schemas and malformed input. Failed requests return a short error code and no
partial trace. Only synthetic fixture contents should be supplied.

This boundary follows the official [Dart C interop guide](https://dart.dev/interop/c-interop)
and [cgo pointer/export rules](https://pkg.go.dev/cmd/cgo), checked 2026-09-30.
It adds no third-party package dependency.

## Independent financial candidate (P01 continuation)

`finance.dart` independently implements arbitrary-precision reduced rationals,
FIFO automatic receipts, charges, paired Ponzi, forgiveness, financial Coup,
ordinary financial closure, explicit finish/finalize, next-game admission and
snapshot nullification. It imports no FFI adapter and reads no expected output.
The Go ABI accepts `cgms-offline-finance-probe-v1` with `ledger`, `game_limit`
(1–3) and at most 64 scenario `commands`. Financial seats are zero-based;
creditor −1 means the system. Every frame includes the full private ledger,
exact totals, competition ranks, completion status, each seat's restricted debt
projection and the narrow finish-only financial bot decision.

Six generated fixtures cover:

- Three financially finalized games for each of three and four seats, including
  explicit settlement finishes, zero cash between games, immutable first-game
  results, exact Ponzi halves, carried debt and cross-game nonspendable forgiveness
  surviving Coup (§§4.2/4.4, F04/N06). These are complete **financial scenario
  matches**, not dealt-and-played card matches or promise/reputation journeys.
- Reciprocal debts of 1 with a 1/3 receipt, using an independent unbatched Dart
  FIFO oracle against Go's optimized settlement; no reciprocal netting or rounding.
- A rational numerator above 2^53; same-game forgiveness retry followed by Coup;
  and nullification restoring the synthetic retained start snapshot.

The runner compares every state field and permitted observation after every
command, then restarts from every JSON-serialized frame. Independent isolates
and two fresh processes repeat the comparisons. Invalid schemas, unknown top-level
fields, negative cash/receipts, wrong-game commands, premature finalization and
unsupported operations reject without partial traces. Go tests also assert
rule-derived scores and fixed match length independently of generated output.

The Dart entry point consumes the complete decoded command objects emitted by
Go's fixture exporter. It is not a hardened arbitrary-JSON decoder; omitted fields,
duplicate raw keys and malformed nested object behavior are not claimed equivalent.
Nullification snapshots are trusted synthetic inputs, not client-authenticated
provenance. Neither candidate's probe exports a production save/load API.

Native receipt work is limited to 4,096 settlement segments; other native
financial helpers admit only small acyclic settlements (their existing engine
boundary). Dart refuses a trace exceeding 4,096 unbatched work units, returning
no partial result. Those probe admission limits do not amend legal obligations;
large-cycle resumable Dart settlement remains unimplemented. Departure, voluntary
transfers, full board eligibility, promise/reputation settlement and complete
financial bot policies remain outside this candidate. This is partial F04/N06
coverage, not proof of the entire financial lifecycle or full offline engine.

`report.json` now includes `finance_runs` with six fixture populations in two
fresh processes. Each uses five warmups and thirty timed samples; native calls
include the ABI copy/JSON path, and Dart calls include input JSON decoding and
result JSON encoding. Exact comparison is outside the timed region. Host timings
are whole scenario traces, not mobile decision-latency evidence or an engine
selection. All generated fixtures and measurement reports remain private ignored
research artifacts.

Verified continuation run: `p01-finance-final`, log
`/tmp/agent-runs/p01-finance-final--20260930T192340Z-79420.log`.

traces contain 25/28 frames respectively; the other four fixtures contain

## Independent card-play comparison and provisional choice

`cardplay.dart` is an independent SDK-only board/lifecycle candidate, with its
own card movement, initiative ranking/tie draws, opening history, ordered
responses, turn/round scheduler, scoring, financial closure, match progression,
seat projection, passive decision policy and canonical SHA-256 implementation.
It never loads Go, reads expected fixtures or copies successor fields. Chance
permutations are explicit common inputs; this does not compare independent RNGs.
The separate test harness alone reads reference data or invokes native FFI.

`cgms-offline-cardplay-v1` admits a narrow, explicit rule profile: normal deals,
initiative with tie resolution, number-card series openings/additions, all-pass
response windows, draws, end turns, thirteen-round ordinary closure, settlement
finish/finalize and three-game progression. Unsupported command families,
restricted cards, alliances, confinement, departures, pending accounting,
effects and other excluded state reject without partial output. It is neither
a complete Dart rules port nor a hardened arbitrary save-file loader.

Two deterministic, normally shuffled fixtures play **six distinct games**:

| Population | Games | Turns | Openings/additions | Response passes | Full frames | Restart boundaries |
|---|---:|---:|---:|---:|---:|---:|
| Three | 3 | 117 | 94 | 188 | 573 | 572 |
| Four | 3 | 156 | 72 | 216 | 660 | 659 |

Every game reaches the natural thirteen-round rule ending; no forced result or
financial-only scenario is counted as card play. At each frame the harness
compares the entire canonical match state, events, every seat observation and
policy choice, then compares native frame digests and the final full frame.
Every serialized checkpoint is restored into both candidates and its next
transition rechecked. Independent Dart isolate replay, wrong-game, unsupported
operation, invalid chance permutation and invalid-state tests also run.

Both policy implementations receive only the acting seat's authorized
observation and public lifecycle/own opening flags. They open eligible series,
pass responses and end turns. This is a **passive workload policy**, with no
claim of competent play, difficulty differentiation or measured playing strength.
Combat, purchases, confinement, powers, alliances, loans and discretionary
promise/departure journeys are absent. Broader independent ledger scenarios
above remain separate evidence and do not fill those board-coverage gaps.

The runner verifies the trace in two fresh processes and measures Dart-only and
native candidates in separate fresh processes. Each whole-match timing has one
warmup and three samples, including serialization and complete frame hashing.
For each open/pass/end-turn policy branch it reports 100 decision samples after
ten warmups, including JSON and (for native) ABI overhead. RSS includes the Dart
VM and, only for native, the Go runtime; later population peaks retain earlier
process history. These are descriptive host measurements, not engine-only
memory, statistical tail estimates, mobile budgets or bot-evaluation samples.

**Provisional recommendation: use the shared Go engine through an explicit
native offline boundary.** It retains the accepted full rules implementation
and avoids maintaining a second rules engine. The independent Dart candidate
provides exact differential evidence for the documented reachable subset;
it does not establish full-port coverage or justify choosing a partial engine
for offline gameplay. Performance measurements describe this policy and adapter,
not a universal Go-versus-Dart advantage. Final choice, packaging and actual
Android/iOS execution remain subject to R06N; P02 must add a production local
boundary, durable saves, legal/competent difficulty tiers and tutorial journeys.
